# N30 Pro 统一设备管理页面 — 实现需求

## 目的
新增独立 LuCI 页面「网络 → 设备管理」，将 DHCP、邻居表和 MTK 闭源 Wi-Fi 的无线客户端列表合并。不能仅安装一个品牌识别插件就宣称完成。

## 页面列
| 设备名称 | 品牌/厂商 | IPv4 地址 | MAC 地址 | 连接方式 | 在线状态 | 上传/下载流量 | 限速操作 |
|---|---|---|---|---|---|---|---|

- 设备名称：用户自定义名称优先，其次 DHCP hostname、无线主机名，最后显示未知设备及 MAC 后缀。
- 品牌：本地 OUI 查到的厂商；随机 MAC 或不可靠的 OUI 显示「未知」，用户可自定义品牌备注。**禁止根据主机名臆造真实品牌**。
- IP/MAC：DHCP 租约、`ubus`、`ip neigh` 汇总。无 IP 时显示「未知」，不要编造。
- 接入方式：从 MTK mtwifi 客户端关联表与桥端口匹配；区分 2.4 GHz / 5 GHz / 有线 / 未知。只有硬件提供可信频段数据时才填。
- 在线状态：按邻居表可达状态、无线关联与 DHCP 租约联合判断。只有 DHCP 租约不算可靠在线。
- 流量：有 nlbwmon 记录时显示累计上传/下载；无法按 MAC 统计时标注来源及限制。
- 排序/搜索：支持按在线状态、名称、IP、品牌筛选。
- 修改名称：以 MAC 或固定 DHCP 身份为键保存用户设备名及备注，不能把设备名直接写成厂商真值。
- 设备限速：独立上传和下载的设置入口。只有在路由器实际控制所需流量路径时才启用；AP 二层桥接/硬件卸载可能绕过限制。未验证显示「未验证」而非成功。

## 验收条件
1. 生成的固件中真正存在 LuCI「设备管理」菜单、JS 页面、RPC/ubus 后端和 ACL。
2. 页面能合并 DHCP 与 MTK 闭源 Wi-Fi 连接数据，而非只显示静态租约。
3. 无品牌时明确标未知，可以手动命名。
4. 没有成功验证的限速规则不显示已生效。
5. 提供在真实路由器上检查可读信息源的命令及测试步骤，不得为了读取数据降低权限控制。
6. 保留 Argon 3.0、PassWall2、MTK mt_wifi 和 Bootstrap fallback。
7. 固件编译成功与实机功能验收分别记录。
